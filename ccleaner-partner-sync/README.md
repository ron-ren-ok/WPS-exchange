# CCleaner Partner Sync

从 Gmail 读取主题为 `CCleaner - WPS - B - Daily Report PBI` 的已验证邮件及其 PDF 附件，并写入 Google Sheet「合作方新增血量」长表。

- 合作方固定为 `CCleaner`，运营位固定为 `气泡`。
- 第 1 页 `Split by Date & Geo` 中，安装量 `Total` 写入 `新增`，Costs 的美元 `Total` 写入 `血量`；两张表分别按各自日期列对齐。
- 只有同一份报告中某日的 `新增`、`血量` 都齐全才更新或追加；缺任一指标则整日跳过，不跨报告拼接指标。明确的数值 `0` 是有效数据。
- 两张表必须各有日期头；文本列数不匹配时拒绝推断。PDF 空列优先通过列坐标识别，保留其他日期的完整指标对；无法确定归属的表仅记录诊断，不写入其数据。
- 默认按北京时间昨天截止，覆写此前连续 7 个自然日（包含昨天）。例如 9 月 28 日运行，写入范围是 9 月 21–27 日。邮件查询覆盖该开始日至今天，从新到旧选择最新有范围内完整指标对的有效 PDF；报告缺失日期会跳过并记录。
- 手动指定日期时，按邮件发送日期查询包含起止日的历史邮件，并仅覆写相同数据日期范围；同日采用较新邮件中的完整指标对。只填结束日期时开始日期默认提前 6 天，只填开始日期时结束日期默认昨天。若报告延迟至范围结束日之后发送，需要扩展查询结束日。
- 以「日期 + 合作方 + 运营位」定位记录。完整指标对中的数值覆盖已有记录，不存在则追加；未变化的值不重复写。
- 动态读取 `A:E`，不设 10000 行截止；先筛选 `CCleaner/气泡` 再解析日期，仅检查该同步范围内的目标记录唯一性，其他合作方异常不阻断同步。
- 网络请求超时 30 秒，临时错误最多重试 3 次（等待 1、2、4 秒）；追加响应丢失后先重新读取确认，只重试尚未存在的记录。写后重新读取核对两项指标。
- Actions 串行执行 CCleaner 同步，任务超时 20 分钟，启用 pip 缓存。该串行控制覆盖此工作流，外部脚本仍需避免同时写同一 CCleaner 记录。
- 只接受 `no-reply-powerbi@microsoft.com` 直接发送的邮件，或正文可验证该原始发件人的 `partner@wps.com` 转发。

GitHub Actions 每天北京时间 03:00（UTC `19:00`）自动运行，也可手动指定开始和结束日期。复用 Avast 同步的三个 Secrets：`GOOGLE_SHEET_SERVICE_ACCOUNT_JSON`、`GMAIL_IMAP_USERNAME`、`GMAIL_APP_PASSWORD`。

只使用 Actions 日志，不推送 webhook。日志记录邮件 UID、附件名、邮件日期、可用报告日期、缺失日期、解析诊断、陈旧报告提示、覆写明细、写后核验数量，以及邮件/PDF、读表、写表、核验各阶段耗时。没有任何完整指标对时不写表并返回失败。

本地验证：`python -m unittest discover -s ccleaner-partner-sync/tests -v`。
