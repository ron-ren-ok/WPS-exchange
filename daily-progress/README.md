# WPS 日进度播报

此任务只读 Google Sheet，通过 WPS 群机器人发送一张合并的日进度与月度预测卡片；不使用 AI，也不修改表格数据。

## 卡片展示

- 血量、360 新增分别展示已回传、预测回传、月底预测和完成率；月目标放在指标标题内，两个指标之间用分隔线区分。
- 预测回传 = 已回传 + 未回传；删除原来的已回传、未回传、后续预测分项数值行。全部图例放在一起，目标位置位于预计缺口图例右侧。
- 两条加长的灰色分隔线分别位于两个指标之间、360 新增结论下方；先展示数据完整性及合作方名单，再展示共享图例。
- 使用带颜色的字符进度条：蓝色实心 `▰` 为已回传，橙色实心 `▰` 为未回传，蓝色空心 `▱` 为后续预测，灰色实心 `▰` 为预计缺口，`│` 为目标位置。字符按比例近似展示，精确数值见文字。
- 未回传仍是现有算法估算的缺失日期数值；只缩短展示文案，不改变计算口径。
- 达标或预计达标时不显示灰色尾巴；预计未达标时显示灰色缺口，并显示 `预计缺口 xx.xx 万人`。
- 已达标血量显示 `实际超目标 xx.xx 万 · 预计超目标 xx.xx 万`。
- 数据状态只显示 `⚠ 数据不全 · N 个合作方` 和合作方名单；不显示滞后天数或后续日均需完成量。
- 无需生成、上传或公开存储图片。运行时数据不写入 GitHub 源码、日志或公开 artifacts。

## 数据逻辑

- 只读取「合作方新增血量」长表的表头：`日期`、`合作方`、`运营位`、`新增`、`血量`。
- 不读取「日进度追踪」，不依赖其中的公式、固定单元格或固定列。
- 血量自动汇总当月全部合作方与运营位；新增自动汇总合作方为 `360` 的所有运营位。
- 沿用现有播报算法：先按合作方汇总所有运营位，每个合作方独立按最近最多 14 个有数据的观测日均值补齐到统计截止日和月底，再汇总。
- 仅从「目标完成度」读取当月血量目标（B 列）和「合作方新增目标」区域中 360 的目标，不读取实际完成公式。

## GitHub Secrets

在仓库 **Settings → Secrets and variables → Actions** 中配置：

- `GOOGLE_SHEET_SERVICE_ACCOUNT_JSON`：可读取目标表格的服务账号 JSON；服务账号邮箱须以查看者身份共享到该表格。
- `WPS_WEBHOOK_URL_TEST`：测试阶段使用的 WPS 群机器人 webhook 地址。
- `WPS_WEBHOOK_URL`：正式 WPS 群机器人 webhook 地址。
- `WPS_WEBHOOK_KEY` 和 `WPS_WEBHOOK_SECRET`：仅当机器人启用签名校验时成对配置。

工作流每天北京时间 04:00 向正式群自动播报。手动触发默认 `test`，也可明确选择 `production`。测试地址缺失时直接失败，不回退到生产地址。

卡片生成命令：

```powershell
python scripts/prepare_progress_card.py --output <body.md> --subtitle-output <subtitle.txt>
```

可用 `--end-date YYYY-MM-DD` 指定统计截止日，默认北京时间昨天。确认秘密配置后，使用现有 `scripts/send-wps-webhook.ps1` 的 `-CardTitle`、`-CardSubtitle` 和 `-CardText` 发送。
